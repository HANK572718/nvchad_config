OSC52 剪貼簿直通

讓 tmux 裡的 nvim（本機與 SSH 遠端一致）按下 v 圈選、y 複製後， 內容直接落進你面前這台 Mac 的系統剪貼簿；而 dd、x 這些刪除動作不再洗掉剪貼簿。

macOS · Darwin 25.6 nvim 0.11.7 tmux 3.7b Ghostty 1.3.1 TERM=xterm-ghostty 2026-09-19

01先講結論

實測之後，原本的假設有兩處不成立，規劃內容因此和「直覺答案」不同。

本機那條路其實早就通了。 NvChad 的 nvchad.options 已經替你設了 clipboard = "unnamedplus"，而 nvim 在這台 Mac 上抓到的 provider 是 pbcopy。所以本機 v + y 現在就會進系統剪貼簿—— 代價是 dd / x / ciw 也一起進去，剪好的東西常被誤刪洗掉。

真正斷掉的是 SSH 遠端那條，而且斷點在 tmux。 tmux 的 set-clipboard 目前是預設值 external， 實測會把「應用程式送出的 OSC52」整段吞掉，不轉發給外層終端機。 遠端 nvim 再怎麼送都到不了 Ghostty。

02實測證據

用一個完全隔離的巢狀 tmux 做的：私有 socket 另起一個 tmux server，外層用 pipe-pane 捕捉原始位元組。沒有碰你正在用的 tmux session，也沒有動到系統剪貼簿 （你剪貼簿裡那份帶 RTF 格式的內容原封不動）。

A. tmux 到底轉不轉發應用程式的 OSC52

set-clipboard 捕捉位元組 抓到的 ]52;c;… 結果
external　（目前狀態） 83 1 次 — 只有指令本身的畫面回顯 未轉發
on 107 2 次 — 回顯 ＋ 真正的 ESC ] 52 序列 已轉發

多出來的那 24 bytes，就是被轉發出去的 OSC52。這是整個規劃唯一的必要修正。

B. 遠端主機 terminfo 沒有 Ms 會不會壞掉

tmux 手冊說轉發需要 terminfo 有 Ms 這項能力。而本機實測： xterm-ghostty 有 Ms、tmux-256color 沒有。 網路上的標準食譜因此都會叫你加一行 terminal-overrides 強制宣告 Ms。 我把外層 TERM 換成沒有 Ms 的 tmux-256color 來驗這條到底需不需要：

外層 TERMMs override結果
tmux-256color（無 Ms） 沒加 仍然轉發
tmux-256color（無 Ms） 加了 轉發

那條食譜在你的版本上是多餘的。 tmux 3.2 之後改用 terminal-features 並在 attach 時發 ESC[>q 主動問終端機是誰，能力是動態協商出來的，不再只看 terminfo。 我們實測 on 這組的 terminal-features 已經是 xterm*:clipboard:…。

但它對舊 tmux 的遠端主機仍有意義：tmux 3.0 / 3.1（Ubuntu 20.04、Jetson L4T 那類 LTS 映像常見） 沒有 terminal-features，只能查 terminfo。所以這行會加、但標註為「舊版保險」， 而不是冒充成必要修正。對不支援 OSC52 的終端機來說，多送的序列會被忽略，不會亂碼。

03改動清單

三個檔案。tmux 一段、nvim 一段、文件一份。

script/devtools/tmux.conf 新增一段（放在「終端相容性」之後） 
# --- 剪貼簿：讓應用程式送出的 OSC52 穿過 tmux ---
# tmux 預設 set-clipboard=external。手冊只說 external 會「嘗試設定終端機剪貼簿」，
# 沒說清楚它對「應用程式送來的序列」怎麼處理——實測（tmux 3.7b，巢狀 tmux +
# pipe-pane 捕捉原始位元組）是整段吞掉，不轉發。只有 on 會接受並往外送。
# 這是遠端 nvim 的 OSC52 到不了本機剪貼簿的唯一原因。
set -s set-clipboard on

# 舊版保險（非必要）：tmux < 3.2 沒有 terminal-features，判斷外層終端支不支援
# OSC52 只能查 terminfo 的 Ms 能力；遠端主機常常沒有 xterm-ghostty 這個條目。
# 本機 3.7b 實測不加也通（會用 ESC[>q 動態協商），純粹是給 Ubuntu 20.04 /
# Jetson L4T 那類舊 tmux 的遠端用。終端機不支援時會忽略此序列，不會亂碼。
set -ag terminal-overrides ',*:Ms=\E]52;%p1%s;%p2%s\007'

生效方式：set-clipboard 是 server option， prefix + r 重載不夠，要 tmux kill-server。 這點 repo 的 tmux.conf 在圖形協定那段已經自己註記過，一致對待。

lua/configs/clipboard.lua 既有模組，加三塊

這個模組已經做好「本機用原生 provider、SSH 用 OSC52」的分支，不動它。加的是下面三塊。 

-- ① 解除 NvChad 的 unnamedplus。
--    lua/options.lua 第一行 require "nvchad.options" 會設 clipboard=unnamedplus，
--    那讓 d / x / c 一起覆蓋系統剪貼簿。本模組在其後才跑，可以蓋掉。
vim.opt.clipboard = ""

-- ② 只鏡射「真正的 yank」到 + register。
local grp = vim.api.nvim_create_augroup("ClipboardYankMirror", { clear = true })
vim.api.nvim_create_autocmd("TextYankPost", {
  group = grp,
  desc = "把 y 的內容同步到系統剪貼簿（刪除動作不受影響）",
  callback = function()
    local ev = vim.v.event
    -- operator ~= "y" 擋掉 d / c / x；regname ~= "" 保留 "ay 這種指定暫存器的用法
    if ev.operator ~= "y" or ev.regname ~= "" then return end
    if use_osc52 and exceeds_osc52_limit(ev.regcontents) then return end
    vim.fn.setreg("+", ev.regcontents, ev.regtype)
  end,
})

-- ③ 解除 unnamedplus 之後 p 不再貼系統剪貼簿，補一個對稱的按鍵。
vim.keymap.set({ "n", "v" }, "<leader>p", '"+p', { desc = "貼上系統剪貼簿" })

另外兩個小補強

  • 大量 yank 的保險絲。OSC52 走的是終端機序列，tmux 與各家終端機都有沒寫進文件的長度上限， 超過會靜默截斷——你以為複製成功、貼出來少一半，這是最難察覺的失敗。 超過門檻就 vim.notify 告訴你改用 "+y，不要假裝成功。 門檻給預設值並開放 vim.g 覆寫。只在 OSC52 路徑檢查，本機 pbcopy 沒這問題。
  • is_remote() 加手動覆寫。目前只看 SSH_TTY / SSH_CONNECTION / SSH_CLIENT。你要涵蓋 Windows 遠端，而 Windows OpenSSH 注入這些變數的行為不像 Unix sshd 那樣可靠， 我也無法從這台機器驗證。加一個 NVIM_CLIPBOARD_OSC52=1/0 的逃生門， 偵測失準時不必改程式碼就能救。
docs/CLIPBOARD_OSC52_GUIDE.md 既有文件，補實測章節

這份文件的 WHY / HOW 寫得完整，但它現在告訴讀者 tmux 要 set -g set-clipboard on，而實際部署的 tmux.conf 裡根本沒這一行—— 文件與設定不一致，正是這次踩到的坑。要補的是：

  • external vs on 的實測對照表（就是上面那張），連同判讀方式
  • Ms 那條食譜「在 3.2+ 是多餘、在舊版才需要」的界線
  • 三層自檢指令：tmux show-options -s | grep clipboard、 infocmp -x $TERM | grep Ms、nvim 內 :lua print(vim.o.clipboard)
  • 把 docs/development-notes/ 的筆記依全域規範一併補上（附 mermaid 鏈路圖）

那支隔離探針腳本我會收成 script/devtools/osc52-probe.sh， 以後換機器或升 tmux 可以直接重跑驗證，不用再臨時寫一次。

04你會感覺到的取捨

這些是行為改變，不是 bug，先講在前面。

  • p 不再直接貼系統剪貼簿。這是解除 unnamedplus 的必然代價。 替代有三條：<leader>p、原生 "+p、 或直接用 Ghostty 的 Cmd+V（insert 模式下走 bracketed paste，最順）。
  • dd 之後 p 的行為不變。刪除仍然進 nvim 自己的暫存器， nvim 內部剪下貼上完全照舊——改的只是「刪除不再外洩到系統剪貼簿」。
  • set-clipboard on 會讓 tmux 額外把內容存成自己的 paste buffer。 多一份記憶體，換來 prefix + ] 也能貼同一份內容。可接受。
  • OSC52 的貼上（讀回）仍然不通，這是刻意的。 終端機預設擋掉 OSC52 讀剪貼簿，否則遠端主機能偷走你本機剪貼簿裡的東西。 你的 configs/ghostty.config 把 clipboard-read 留在預設的 ask，是對的，不動它。

05驗收步驟

每一步都有明確的預期輸出，對不上就是沒改成功。

  1. tmux kill-server 後重開 tmux

    → tmux show-options -s | grep clipboard 要顯示 set-clipboard on

  2. 本機 nvim：v 圈選一段 → y → 終端機跑 pbpaste

    → 印出剛才選的那段

  3. 接著在 nvim 裡按 dd，再跑一次 pbpaste

    → 內容不變（這是這次改動的重點，刪除不再汙染剪貼簿）

  4. SSH 進遠端（Linux / Jetson 先測），tmux + nvim 裡重複第 2 步，回本機 pbpaste

    → 印出遠端選的那段。這一步在改動前是必定失敗的

  5. Windows 遠端：先 :lua print(vim.inspect(vim.g.clipboard)) 確認走到 OSC52

    → 顯示 OSC52；若顯示 nil 表示 SSH 偵測失準， 設 NVIM_CLIPBOARD_OSC52=1 再試

  6. 重跑 script/devtools/osc52-probe.sh

    → on 那組 PASS

06這次不做

你沒選的先擱著，但有一項是查的時候撿到的，值得你知道。

  • tmux copy-mode 的 v / y。順帶發現：tmux 3.7b 的 copy-mode-vi 裡 v 其實綁的是 rectangle-toggle（切矩形選取）、y 根本沒綁， 真正複製的是 Enter。如果你按 prefix + [ 之後習慣按 v 再 y， 那是無效操作——跟 nvim 的斷點是兩回事。要補只需兩行 bind-key -T copy-mode-vi，說一聲就加。
  • 滑鼠拖曳選取。現在 mouse on + mouse=a 會把拖曳吃進 nvim 的 visual 選取， 拿不到終端機原生選取。要改得先決定犧牲哪一邊（Ghostty 按住 Option 可暫時拿回原生選取）， 牽涉的取捨跟這次無關。
  • 順手記一筆：.gitignore 目前沒有 .claude/ 與 CLAUDE.md （全域規範第四條），而 .claude/settings.local.json 已經被追蹤。這次不動，留給你決定。
